# フォルダ・圧縮フォルダとファイル操作

画像・動画・音楽ファイル1つ・フォルダ・圧縮フォルダ（zip / cbz）のいずれを開いても、その中のファイルを自然順（`img2.png` → `img10.png`）で前後に移動できます。一覧に並ぶのは常に 1 種類（画像・動画・音楽のどれか）だけです。

## 探索範囲

| 開いたもの | 探索範囲 | 並ぶ種類 |
| --- | --- | --- |
| 画像・動画・音楽ファイル | 同じフォルダの直下のみ（サブフォルダは見ません） | 開いたファイルと同じ種類 |
| フォルダ | 開いたフォルダの直下を 1 層目として 3 層目まで | 並べたとき先頭に来るファイルの種類 |
| 圧縮フォルダ | 書庫の直下を 1 層目として 3 層目まで | 画像のみ（書庫の中の動画・音楽は読みません） |

- 画像を開けば同じフォルダの動画・音楽は飛ばし、動画を開けば画像・音楽を飛ばします（音楽も同様）
- フォルダは 3 層目までの画像・動画・音楽を開いたフォルダからの相対パスの自然順で並べ、先頭に来たファイルの種類だけを残します。たとえば `a/01.mp3` が先頭なら、同じフォルダにある画像・動画は一覧に入りません。画像を見たいフォルダに動画が混ざっている場合は、画像ファイルを直接開いてください
- 4 層目より深い場所のファイルは読みません。ファイルが大量にあるフォルダを開いても一覧が膨らみすぎないようにするためです
- 種類は開いたときに決め、読み直し（`R`・フォルダの変更への追従）でも変えません。空のフォルダを開いた場合だけ、あとから増えたファイルで決まります
- サブフォルダの中のファイルは、開いたフォルダからの相対パス（`ch2/001.png`）で表示します

書庫は 3 層目までの全画像を 1 本のリストにまとめ、フルパスの自然順で並べます。層は書庫の直下から数えます（`book.zip/book/ch1/001.png` が 3 層目）。

- 圧縮ソフトが余計に一層フォルダを挟んだ場合（`book.zip/book/001.png`）でも、そのまま `001.png` から表示されます
- 章ごとにフォルダ分けされた書庫（`book.zip/{ch1/, ch2/}`）は `ch1` → `ch2` と通しで読めます
- 表示名からは全エントリの共通フォルダを取り除くので、単一フォルダの書庫は `001.png`、複数フォルダの書庫は `ch2/001.png` のように出ます
- 一覧を作るときに読むのは索引だけで画像データは読まないため、フォルダがいくつあってもメモリ使用量は変わりません

## 書庫の読み込み

zip の索引（セントラルディレクトリ）だけを読み、表示する画像のみをその都度取り出します。書庫全体をメモリやディスクに展開しないため、数GBの書庫でも起動が一瞬です。

## 関連付け

画像・動画・音楽の各拡張子は OS に関連付けられます（インストーラーが登録するほか、設定ウィンドウの「関連付け」で拡張子ごとに選べます）。関連付けたファイルをダブルクリックすると sView が起動し、上の表のとおり同じフォルダの同じ種類のファイルだけを前後に移動できます。

> [!NOTE]
> `.zip` / `.cbz` とフォルダは sView で開けますが、**OS の関連付けはしません**。解凍ソフトとの関連付けを
> 奪ってしまうためです。ドラッグ＆ドロップか `O` / `D` キーのダイアログから開いてください。

## フォルダの変更への追従

フォルダを開いている間は、その中のファイルの増減を検知して一覧へ反映します。ファイルを追加したあとに開き直す必要はありません。

- 監視は OS のネイティブ通知に任せます（Windows: ReadDirectoryChangesW / macOS: FSEvents）。一定間隔でフォルダを読み直すポーリングとは違い、変化が無い間は OS からの通知を待っているだけなので、CPU もディスクも使いません
- 見る範囲は一覧と同じです。単体のファイルから開いたときはそのフォルダの直下だけ、フォルダを開いたときは 3 層目まで見ます（サブフォルダごとの追加・削除も拾います）
- 一覧に入るのは開いたときに決めた種類だけです。違う種類のファイルが増えても一覧は変わりません
- 通知が届いてから実際に読み直すまで少し（0.8 秒）待ち、その間に届いた通知はまとめて 1 回で処理します。複数ファイルをまとめてコピーしても読み直しは 1 回で済み、コピー途中のファイルを拾いにくくもなります
- 増えた画像は表示中の画像より前にあってもその場で一覧に入り、表示中の画像はそのまま見続けられます（枚数の表示だけが変わります）。表示中の画像が外から消された場合は次の画像へ移ります
- 圧縮フォルダ（zip / cbz）を開いている間は動きません。書庫が差し替わった場合は `R` で読み直してください
- ネットワークドライブなど監視が効かない場所もあります。設定「フォルダの変更を自動で取り込む」をオフにすれば監視自体を止められ、どちらの場合も `R` で手動の再スキャンができます

## 画像の削除

`Del` キー（macOS では `⌘ Delete` でも可）か、右クリックメニューの「ゴミ箱へ移動」で、表示中の画像を OS のゴミ箱（Windows: ごみ箱 / macOS: ゴミ箱）へ移動できます。完全削除はしないので、消し間違えても OS 側から戻せます。

- 既定では確認ウィンドウが出ます。その中の「今後確認しない」をチェックして実行すると、設定「削除の前に確認する」がオフになり、次からは確認なしで移動します（設定ウィンドウからいつでも戻せます）
- 削除すると同じ位置の次の画像へ移ります。最後の 1 枚を消した場合は、起動直後と同じ「ドロップ待ち」の表示に戻ります
- 圧縮フォルダの中の画像は、ファイルとして存在しないので削除できません（メニューでも選べません）
